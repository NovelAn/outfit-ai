# 衣橱单品编辑与删除设计

日期：2026-08-03  
状态：已确认，待实施

## 1. 目标

当 rembg 去背景或 MiniMax VLM 识别不准确时，用户可以从现有衣橱界面修正单品信息，或删除整件单品。沿用用户确认的 Stitch React 页面，不新增独立页面。

## 2. 交互

1. 用户点击衣橱卡片，继续打开现有单品详情浮层。
2. 详情态新增“编辑信息”和“删除单品”入口。
3. 编辑态开放：单品名称、分类、主色、辅色、材质、厚薄度、版型、适用季节、场景和风格标签。
4. “保存修改”成功后关闭编辑态，并用后端返回的数据立即刷新当前卡片和详情。
5. “取消”放弃本次本地修改，不发送请求。
6. “删除单品”必须经过二次确认；确认后删除数据库记录、原图和 `.nobg` 去背景图，并从衣橱列表移除。
7. 保存或删除请求进行中禁用重复操作；失败时保留当前单品并显示中文错误提示。

图片替换、手工抠图和重新调用 AI 不在本次范围内。

## 3. 数据与接口

- 读取详情：复用 `GET /api/wardrobe/{id}`。
- 保存修改：复用 `PATCH /api/wardrobe/{id}`，不新增路由。
- 删除单品：复用 `DELETE /api/wardrobe/{id}`，不新增路由。
- 前端 API 层新增 `updateWardrobe(id, data)`；复用已有 `deleteWardrobe(id)`。
- 后端已有的 `WardrobePatch` 字段直接保存名称、分类、颜色、材质、版型、季节、场景和风格标签。
- 当前数据表没有独立“厚薄度”列。为避免仅为一个展示属性执行数据库迁移，厚薄度使用 `tags` 中唯一的受控值保存：`轻薄`、`适中`、`厚实`；编辑时替换旧厚薄度标签并保留其他标签。
- 分类继续使用稳定内部码：`top`、`bottom`、`shoes`、`accessory`；已有 `outerwear`、`dress` 可正常显示和编辑，不改变现有数据。

## 4. 前端状态

详情浮层维护最少状态：当前详情、是否编辑、表单草稿、是否保存、是否删除和错误信息。进入编辑时从当前详情复制草稿；只有保存成功才更新列表事实状态。

删除成功后清空选中项并刷新/过滤本地列表；删除失败不乐观移除，避免界面与后端不一致。
