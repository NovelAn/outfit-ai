# 上传与灵感体验修复设计

## 范围

本次只修复人工测试确认的四项问题，不改变 Stitch ZIP 的页面结构、导航或整体视觉：

1. MiniMax-M3 返回 `<think>...</think>` 等前缀时，结构化 JSON 解析失败。
2. 灵感参考图只能单选上传。
3. 灵感存档图片过大，无法快速浏览，也不能原位放大查看。
4. iPhone `.jpg` 可能被 Pillow 识别为 MPO，导致真实衣橱上传失败。

## 设计

### 后端

- 在共享 `generate_json()` 边界兼容纯 JSON、Markdown JSON 代码块，以及 JSON 前存在思考文本的响应；仍由 Pydantic 做最终结构校验，失败继续沿用现有修复重试。
- 图片存储按实际内容验证。Pillow 识别为 `MPO` 时取主画面并按标准 JPEG 重编码；路由不因浏览器缺失或非标准的 MIME 上报而提前拒绝合法图片。
- 不新增依赖，不改变数据库或 API 路径。

### 前端

- 灵感上传的文件输入启用多选，对所选图片逐张调用现有上传和状态接口。
- 批量任务独立结算：成功图片进入灵感库；单张失败不阻断其他图片；最终提示成功与失败数量。
- 灵感存档改为三列紧凑缩略图。缩略图使用固定比例和 `object-fit: cover`；点击图片显示覆盖层中的完整图，再次点击图片关闭并回到原滚动位置。
- 处理状态保留为缩略图角标；批量选择与删除行为保持不变。

## 错误处理

- JSON 提取后仍不符合目标 schema 时，继续返回现有 LLM 结构化输出错误。
- 真实不受支持或损坏的图片仍返回明确的 `400/415` 错误。
- 批量上传只汇总失败数量，不删除已成功的项目。

## 验证

- 后端回归测试覆盖带 `<think>` 的 JSON 与 MPO/JPG 存储。
- 前端契约测试覆盖灵感多选输入、三列网格和图片放大/恢复交互。
- 运行后端完整测试与 lint、前端测试/lint/build，并在 `390 × 844` 手机视口走查上传入口和灵感存档。
