# Outfit-AI 移动端前端 PRD（Stitch 生成版）

版本：v1.0
日期：2026-07-29
目标：用于 Google Stitch 生成一套可落地的移动端高保真界面，后续由开发侧融合现有 uni-app 前端与 FastAPI 后端。

> 2026-07-30 实施备注：用户选定的 Stitch 导出稿采用暖纸张、深海军蓝与锈红的编辑式视觉；该实际产物覆盖本文早期视觉描述，产品流程与真实性约束保持不变。

## 1. 产品定义

Outfit-AI 是一个以真实衣橱和长期个人品味为核心的 AI 穿搭工具。

产品解决两个不同问题：

1. **今天怎么穿**：基于用户真实拥有的衣物、长期 Style DNA、当次灵感参考、季节和场景，生成 Safe / Fresh / Stretch 三档穿搭。
2. **以后想怎么穿**：不受真实衣橱限制，生成新的穿搭灵感图，帮助用户探索换季风格、未来购物方向和新的搭配可能。

产品不是电商商城、虚拟试衣或社交社区。它首先是一套个人衣橱操作系统。

## 2. 用户价值

### 2.1 真实衣橱价值最大化

- 用户通常不是缺衣服，而是忘记已有衣物，或者缺少新的组合灵感。
- 推荐必须只使用用户已经确认过的真实单品。
- 不优先推荐“闲置率最高”的衣物，也不做利用率排行榜。
- 推荐主要跟随 Style DNA；在风格合格的候选中保留适度随机性，让不同衣物自然获得曝光。

### 2.2 长期品味理解

- 用户不需要填写抽象的 `style` 或 `preference` 表单。
- 用户通过上传杂志截图、达人 Look、街拍或其他穿搭参考图表达喜好。
- AI 从图片中理解调色板、廓形、层次、材质、风格关键词、季节和场景。
- 所有参考图默认进入长期灵感库，并持续更新用户的 Style DNA。
- 用户如有明确要求，可补充一句自然语言，例如“今天想更正式一点”。

### 2.3 面向未来的风格探索

- 灵感生图不要求使用真实衣橱单品。
- 生成结果必须明确标注为 AI 灵感图。
- 它用于启发，而不是承诺图中商品真实存在或可以直接购买。

## 3. 目标用户

- 有一定衣物数量，但每天仍觉得“不知道穿什么”的用户；
- 会收藏杂志、社交媒体或达人穿搭截图的用户；
- 希望个人风格逐渐稳定，同时保留探索空间的用户；
- 主要在手机上使用，单次操作时间通常为 30 秒到 3 分钟。

## 4. 产品原则

1. **图片先于表单**：优先用图片表达品味，减少文字输入。
2. **真实与灵感严格分开**：真实衣橱推荐不能混入 AI 虚构单品。
3. **默认自动化**：天气和季节自动获取；用户只需快速选择场景。
4. **结果先于设置**：首页尽快进入推荐，不把 Style DNA 配置放在主流程前面。
5. **渐进式复杂度**：高级选项收起；默认操作保持轻量。
6. **状态可信**：上传、识别、去背景、失败和人工确认必须清楚可见。

## 5. 信息架构

底部导航固定为四项：

1. **今日**
2. **衣橱**
3. **灵感**
4. **我的**

### 5.1 今日

承载“基于真实衣橱生成今天穿搭”的主要流程。

### 5.2 衣橱

管理真实单品：上传、AI 识别、去背景、人工确认、查看和编辑。

### 5.3 灵感

管理长期参考 Look，并生成不依赖真实衣橱的 AI 穿搭灵感图。

### 5.4 我的

查看长期 Style DNA、品味备忘录、反馈历史、穿搭历史和基础设置。

## 6. 核心用户流程

### 6.1 首次建立真实衣橱

```text
衣橱空状态
→ 添加衣物照片
→ 上传中
→ AI 识别 + 本地去背景
→ 用户确认类别、颜色等属性
→ 单品进入可推荐衣橱
```

关键要求：

- 上传后立即出现占位卡，不能让用户怀疑操作是否成功。
- 状态使用明确文案：等待识别 / 正在识别 / 等你确认 / 识别失败。
- AI 识别结果必须经过用户确认后才能用于推荐。
- 去背景图用于衣橱和穿搭结果展示；详情页仍可查看原图。

### 6.2 添加长期灵感

```text
灵感页
→ 添加参考 Look
→ 上传杂志截图或达人穿搭
→ AI 分析风格
→ 自动加入长期灵感库
→ 自动更新 Style DNA
```

关键要求：

- 参考图保留完整画面，不做去背景。
- 新上传图片默认进入长期灵感，不再询问是否保存。
- 最新上传图片自动选中，可立即用于“今日推荐”或“灵感生图”。
- 一张参考图可以体现多个风格方向，不强迫归入单一标签。

### 6.3 生成真实衣橱推荐

```text
今日
→ 自动获取天气和季节
→ 快速选择场景
→ 可选：选择一张或多张参考 Look
→ 可选：输入一句特定要求
→ 生成推荐
→ 查看 Safe / Fresh / Stretch
→ 锁定、换一件、反馈或记为今天穿了
```

结果要求：

- 每套展示真实单品图片、名称、类别和推荐理由。
- Safe：熟悉、低风险、容易直接穿。
- Fresh：仍然符合用户风格，但组合更有新鲜感。
- Stretch：适度推动边界，不变成完全陌生的造型。
- 明确展示天气适配和场景适配。
- 真实推荐页面不能出现 AI 生成模特图，以免混淆真实性。

### 6.4 生成独立穿搭灵感图

```text
灵感
→ 选择长期参考 Look（可选）
→ 选择目标季节
→ 选择目标场景
→ 输入一句特定要求（可选）
→ 生成一张 3:4 穿搭灵感图
→ 保存到手机或再次生成
```

结果要求：

- 页面固定显示“AI 灵感图 · 不代表衣橱已有单品”。
- 每次点击只生成一张，避免无意识消耗日额度。
- 请求期间禁用生成按钮，防止重复提交。
- 不自动重试；额度不足或服务失败时给出明确下一步。

## 7. 页面 PRD

### 7.1 今日首页

#### 页面目标

用户在最少操作下获得三套真实衣橱推荐。

#### 首屏内容

- 简洁日期或问候；
- 当前城市、天气、体感温度和自动判断的季节；
- 场景快速选择：日常、通勤、约会、聚会、旅行；
- “今天参考这些 Look”横向图片带；
- “添加参考”入口；
- 一行可选文字要求，默认收起；
- 主按钮：“用我的衣橱搭配”。

#### 推荐结果

- Safe / Fresh / Stretch 三套纵向结果；
- 每套以真实去背景单品构成视觉主体；
- 支持锁定整套或单件；
- 支持换一件、喜欢、不适合、今天穿了；
- 锁定后重新生成时保留已锁定单品。

#### 状态

- 衣橱不足：明确提示至少需要上装、下装和鞋；
- 无定位：显示城市手动输入，不阻断其他操作；
- 加载：展示三套结构化骨架，而不是全屏转圈；
- 服务不可用：显示“无法连接造型服务，请检查网络后重试”，不能显示 `request:fail`。

### 7.2 衣橱页

#### 页面目标

让用户快速理解自己拥有什么，并低摩擦添加新单品。

#### 内容

- 顶部显示衣物总数和类别筛选；
- 真实衣物采用图片网格；
- 图片优先，文字只保留名称、类别和状态；
- 固定或悬浮“添加衣物”按钮；
- 支持查看单品详情和编辑 AI 属性；
- 未确认单品单独显示，不混入已确认衣橱。

#### 卡片状态

- 等待识别；
- 正在识别；
- 等你确认；
- 已确认；
- 识别失败，可重试。

### 7.3 衣物确认页

#### 页面目标

用户快速校正 AI 识别结果并确认入库。

#### 内容

- 大幅去背景衣物图；
- 可切换查看原图；
- 名称、类别、主色、辅色、材质、版型、正式度；
- 风格、季节和场景标签；
- 主按钮：“确认加入衣橱”；
- 次操作：“重新识别”。

表单保持短而可扫视，不把所有字段压进一张密集卡片。

### 7.4 灵感页

#### 页面目标

同时完成长期参考图管理和未来风格探索。

#### 页面结构

1. 最近灵感参考；
2. 添加参考 Look；
3. 当前 Style DNA 摘要；
4. 灵感生图工作区；
5. 最近生成结果仅保留当前会话，不要求建立永久图库。

#### 长期参考图片带

- 采用接触表或胶片带式横向图片布局；
- 图片保持原始比例和完整人物 Look；
- 多选状态清晰；
- 新上传图片自动选中；
- 每张图片可显示少量 AI 风格标签，但不能覆盖主体。

#### 灵感生图区

- 季节选择：春、夏、秋、冬；
- 场景选择：通勤、周末、约会、旅行、正式活动；
- 可选文字要求；
- 主按钮：“生成新的穿搭灵感”；
- 结果图为 3:4；
- 提供“再生成一张”和系统原生“保存图片”。

### 7.5 我的页

#### 页面目标

让用户理解 AI 如何认识自己的长期品味，但不要求频繁配置。

#### 内容

- Style DNA 摘要；
- 核心偏好：调色板、廓形、材质、常用搭配方式；
- 多样风格方向，而不是单一风格标签；
- 品味备忘录；
- 最近学习到的偏好变化；
- 穿搭历史入口；
- 城市和基础设置；
- 手动“刷新我的品味”。

### 7.6 穿搭历史

#### 页面目标

回看真实穿搭，而不是展示 AI 灵感图。

#### 内容

- 日期时间线；
- 真实衣物拼图；
- 场景、天气和 Safe / Fresh / Stretch 标签；
- 喜欢、不适合、今天穿了等反馈状态；
- 点击进入历史详情。

## 8. 关键组件

### 8.1 长期参考 Look 图片带

这是整套产品最具识别度的交互组件。

- 横向滚动；
- 支持上传、多选和取消选择；
- 选中时使用清楚但克制的边框与勾选标识；
- 既出现在“今日”，也出现在“灵感”；
- 不使用复杂拖拽排序。

### 8.2 真实穿搭结果卡

- 以去背景真实衣物图为主体；
- 不使用虚构模特；
- Safe / Fresh / Stretch 语义稳定；
- 理由文案短、具体、可执行；
- 操作不超过四个。

### 8.3 AI 灵感结果

- 3:4 大图；
- 明确 AI 标识；
- 不展示真实 item ID 或衣橱标签；
- 只提供再次生成和保存图片。

### 8.4 上传状态卡

- 图片缩略图；
- 状态名称；
- 简短下一步；
- 失败时提供明确重试按钮。

## 9. 视觉与交互方向

### 9.1 设计关键词

**Contemporary Fashion OS / Image-first / Calm / Precise / Mobile-native**

目标不是时尚杂志排版，而是“高质量个人衣橱工具”：

- 图片是主要信息，文字和容器退后；
- 界面现代、清晰、克制，有真实产品感；
- 适合频繁在手机上操作，而不是只适合展示截图。

### 9.2 建议视觉系统

- 背景：冷白或非常浅的中性灰；
- 主文字：接近黑色的 graphite；
- 辅助文字：中性灰；
- 强调色：单一高识别度的 cobalt blue 或同等冷调强调色；
- 字体：现代无衬线系统字体，不使用衬线标题；
- 圆角：8–14px，避免所有内容都成为大圆角卡片；
- 阴影：尽量不用，优先使用间距、背景层级和细分割线；
- 图片：允许局部全宽或接近边缘，减少厚重卡片包裹；
- 动效：只用于模式切换、选择反馈和结果出现。

### 9.3 明确避免

- 暖米白 + terracotta 的默认 AI 编辑风；
- 大量衬线标题；
- 玻璃拟态、霓虹渐变、发光 AI 按钮；
- 每个区块都是相同大圆角卡片；
- 电商首页式 Banner 和促销视觉；
- 过度奢侈品牌化导致操作密度过低；
- 为了“高级感”牺牲中文可读性；
- 桌面网页缩小成手机尺寸。

### 9.4 设计签名

“长期参考 Look 图片带”是整套产品的视觉签名。它像一条持续生长的个人穿搭胶片，将用户看到的外部灵感连接到真实衣橱和未来探索。

## 10. 内容与文案

文案使用简体中文，直接描述用户能做什么。

推荐：

- “用我的衣橱搭配”
- “添加参考 Look”
- “今天参考这些 Look”
- “生成新的穿搭灵感”
- “确认加入衣橱”
- “AI 灵感图 · 不代表衣橱已有单品”
- “无法连接造型服务，请检查网络后重试”

避免：

- “Submit”
- “AI Magic”
- “解锁你的无限时尚潜能”
- “请求失败：request:fail”
- 技术模型名、API 名或额度内部字段。

## 11. 可访问性和移动端约束

- 基准画布：390 × 844；
- 同时适配 360px 宽度；
- 触控热区至少 44px；
- 文字与背景达到 WCAG AA 对比度；
- 所有选中状态不能只依赖颜色；
- 底部导航和底部主操作不能互相遮挡；
- 页面支持长内容自然滚动；
- 不使用仅 Hover 才能发现的操作；
- 键盘焦点可见；
- 尊重 `prefers-reduced-motion`；
- 兼容 H5、微信小程序和 App，不依赖 DOM 专属能力。

## 12. Stitch 需要生成的画面

请生成一套统一设计系统下的移动端高保真界面，至少包含：

1. 今日首页——未生成推荐；
2. 今日首页——Safe / Fresh / Stretch 推荐结果；
3. 衣橱——有数据的分类网格；
4. 衣橱——上传和识别状态；
5. 衣物确认页；
6. 灵感页——长期参考 Look + 生图输入；
7. 灵感页——AI 灵感图结果；
8. 我的——Style DNA；
9. 穿搭历史；
10. 关键空状态、加载状态和错误状态。

同一页面的不同状态可以作为独立画面生成。

## 13. Stitch 交付要求

生成结果应包含：

- 页面级设计稿；
- 可复用组件；
- 颜色、字体、间距、圆角和图标规范；
- 底部导航；
- 上传、选择、加载、失败和结果状态；
- 真实衣物与 AI 灵感图之间明显不同的视觉语义；
- 可供开发复刻的稳定布局，不依赖难以跨端实现的特效。

如果 Stitch 输出代码，优先要求：

- React 或标准 Web 结构仅作为视觉参考；
- 样式变量集中；
- 不依赖大型 UI 组件库；
- 不把后端调用写死；
- 图片和文案使用可替换的 mock 数据；
- 开发侧后续将其转译到现有 uni-app + Vue 3，而不是直接替换技术栈。

## 14. 后端融合边界

Stitch 只负责前端视觉和交互表达。开发融合时保持以下业务边界：

- 真实衣物上传：`POST /api/wardrobe/upload`
- 衣物状态：`GET /api/wardrobe/{id}/status`
- 衣物确认：`POST /api/wardrobe/{id}/confirm`
- 长期参考上传：`POST /api/style-references/upload`
- 长期参考列表：`GET /api/style-references`
- 真实衣橱推荐：`POST /api/recommend`
- 独立灵感生图：`POST /api/inspiration/generate`
- 反馈：`POST /api/feedback`
- 穿搭历史：`GET /api/history`

前端不得接触 MiniMax Key，也不得直接调用 MiniMax。

## 15. 验收标准

- 用户能在 30 秒内理解“今日”和“灵感”的区别；
- 用户不需要填写 Style 或 Preference 表单；
- 参考图片是核心输入，不是藏在设置里的附加功能；
- 真实推荐只展示真实衣物；
- AI 灵感图有持续可见的真实性提示；
- 首页第一屏能完成场景选择和发起推荐；
- 图片、导航和主操作在 390 × 844 下无重叠；
- 所有关键页面都有空、加载、成功和失败状态；
- 视觉不再呈现 Warm Editorial、米白 terracotta 或衬线主导风格；
- 设计可以被现有 uni-app 跨端实现。

# 可直接粘贴给 Stitch 的生成提示

为 Outfit-AI 设计一套完整的中文移动端应用高保真界面。Outfit-AI 是个人 AI 衣橱操作系统，不是电商商城或社交社区。

应用有两个核心功能：

1. “今日”：根据用户真实衣橱、长期 Style DNA、选中的杂志或达人穿搭参考图、季节和场景，生成 Safe / Fresh / Stretch 三套真实穿搭。结果只能展示用户真实拥有的去背景衣物图片。
2. “灵感”：不依赖真实衣橱，根据长期 Style DNA、参考 Look、季节和场景生成一张 3:4 AI 穿搭灵感图，用于换季购物和新风格探索。结果必须标注“AI 灵感图 · 不代表衣橱已有单品”。

用户不需要填写 Style 或 Preference 表单。用户通过上传和选择杂志截图、达人 Look、街拍等图片表达偏好；这些图片默认进入长期灵感库并更新 Style DNA。仅保留一个可选的自然语言要求输入。

底部导航为：今日、衣橱、灵感、我的。
